# Task 0005: De-risk frozen audio: own ElevenLabs key, verified regeneration, ffmpeg -c copy concat

## Problem

Chapter audio is generated by ElevenLabs (stock voice "George"), but nothing regenerates it: CI runs
`SKIP_AUDIO=1` with no `ELEVENLABS_API_KEY`, so the R2 copy (now backed up) is the only source and we
have no _verified_ ability to rebuild it - the single highest-fragility finding in `audit:0001` (#4).
Separately, the concat step (`renderers/audio/renderer.ts:223` → `ElevenLabsTTS.concatenateMp3s`)
fully re-encodes via ffmpeg (decode→encode, CPU-bound); the segments are sibling MP3s so the concat
demuxer with `-c copy` would stitch them with near-zero CPU (surfaced via VM lag investigation).

## Scope

- Obtain our own ElevenLabs API key (part of the `task:0004` rotation).
- Run the audio pipeline end-to-end for at least one chapter to prove regeneration works (TTS +
  Gemini equation descriptions + concat + R2 layout).
- Change `concatenateMp3s` to `ffmpeg -f concat -safe 0 -i list.txt -c copy out.mp3` (no re-encode).
- Write a short regeneration runbook.

## Out of scope

- Regenerating all audio (the verified backup suffices); changing the voice or audio design.

## Done when

- AC-1: Our own ElevenLabs key is in `.env` (and the GitHub secret if CI regeneration is wanted).
- AC-2: One chapter's audio is regenerated locally end-to-end and verified playable.
- AC-3: `concatenateMp3s` uses the `-c copy` concat demuxer - output plays correctly and CPU/time is
  measurably lower than the re-encode baseline (record before/after).
- AC-4: A regeneration runbook is recorded (steps, env, expected R2 keys).
